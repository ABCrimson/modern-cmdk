## Prerequisites

| Tool | Version | Notes |
|---|---|---|
| Node.js | >= 26.4.0 (`.nvmrc`: Node 28 nightly 28.0.0-nightly20261106ec4d4c2950) | Iterator Helpers (ES2025) and `Symbol.dispose` / `using` (ESNext explicit resource management) run natively |
| pnpm | >= 12.0.0 | Workspace protocol, `pnpm-workspace.yaml` |
| TypeScript | 7.1.0-dev.20261106.1 | Pinned once in the `catalog:` of `pnpm-workspace.yaml` (with react, react-dom, @types/react, @types/react-dom and vite; D54); the root, create-modern-cmdk and playground manifests reference it as `catalog:`, while apps/docs keeps its own `typescript` 6.0.3 pin for vue-tsc (the scoped hold the catalog comment records). Do not install globally |
| Rust + wasm-pack | Pinned nightly (`rust-toolchain.toml`) + wasm-pack 0.15.1 | Only needed if working on `command-search-wasm` |
| Git | >= 2.40 | For Lefthook pre-commit/pre-push hooks |

Verify your setup:

```bash
node --version    # v26.4.0 or higher
pnpm --version    # 12.0.0 or higher
```

## Setup

```bash
# Clone the repository
git clone https://github.com/ABCrimson/modern-cmdk.git
cd modern-cmdk

# Install dependencies (all packages + apps)
pnpm install

# Build all packages
pnpm build

# Verify everything works
pnpm test
pnpm typecheck
pnpm lint
```

Lefthook installs its git hooks via its own postinstall script, which pnpm is permitted to run through the `allowBuilds` entry in `pnpm-workspace.yaml`. Pre-commit and pre-push hooks are active immediately after `pnpm install`; if they are not, run `pnpm lefthook install`.

## Code Style

This project uses **Biome 2.6.6** for both linting and formatting. There is no ESLint or Prettier.

### Formatter settings

| Setting | Value |
|---|---|
| Indent | 2 spaces |
| Line width | 100 characters |
| Semicolons | Always |
| Quotes | Single |
| Trailing commas | All |
| Arrow parens | Always |
| Bracket same line | No |
| Line ending | LF |

The base rule set is Biome's `recommended` preset. Everything below is an explicit
override on top of it, taken from `biome.json`.

### Key lint rules

| Rule | Group | Level | Why |
|---|---|---|---|
| `noUnusedImports` | correctness | Error | Dead code elimination |
| `noUnusedVariables` | correctness | Error | Dead code elimination |
| `useExhaustiveDependencies` | correctness | Error | React hook correctness |
| `noAccumulatingSpread` | performance | Error | No `{...acc, ...item}` in reduce |
| `noBarrelFile` | performance | Error | No `export * from` re-exports |
| `noReExportAll` | performance | Error | Explicit named exports only |
| `useImportType` | style | Error | `import type` for type-only imports (`verbatimModuleSyntax`) |
| `useTemplate` | style | Error | Template literals over `+` concatenation |
| `useExponentiationOperator` | style | Error | `**` over `Math.pow` |
| `noNonNullAssertion` | style | Warn | `!` hides the `noUncheckedIndexedAccess` contract |
| `useButtonType` | a11y | Error | Explicit `type` on every `<button>` |
| `noConsole` | suspicious | Warn | Use structured logging |
| `noAssignInExpressions` | suspicious | Warn | Assignment inside a condition is usually a typo |
| `useIterableCallbackReturn` | suspicious | Warn | Iterator-helper callbacks must return a value |
| `useExplicitType` | nursery | Warn | Explicit return types (required by `isolatedDeclarations`) |

Rules deliberately turned **off** for this codebase: `useSemanticElements`,
`useKeyWithClickEvents`, `useFocusableInteractive` and `useAriaPropsForRole` (the
combobox pattern is hand-rolled against the WAI-ARIA spec, so Biome's heuristics
fight it), plus `noDuplicateCustomProperties` / `noDuplicateProperties` (CSS
fallback declarations are intentional).

<details>
<summary>Per-path overrides</summary>

| Path | Override |
|---|---|
| `benchmarks/**`, `apps/playground/**`, `tests/unit/cmdk-performance-accuracy.test.tsx` | `useExplicitType` and `noConsole` off -- these files print results |
| `apps/docs/**/*.css` | `noImportantStyles` downgraded to Warn (VitePress theme overrides need `!important`) |
| `**/index.ts` | `noBarrelFile` off -- public entry points are barrels by design |
| `packages/modern-cmdk-codemod/src/**` | `noExplicitAny` downgraded to Warn (jscodeshift AST nodes are loosely typed) |

`packages/modern-cmdk/src/react/primitives.ts` and everything under `tests/fixtures` are excluded from Biome entirely via
`files.includes`. The fixtures are byte-exact: each case is an input and the output the transform must produce, compared byte for byte, so a formatter pass over them would change what the tests assert.

</details>

### Import organization

Biome automatically organizes imports via `assist.actions.source.organizeImports`. Import order:

1. External packages (`react`, `radix-ui`)
2. Internal packages (`modern-cmdk`)
3. Relative imports (`./types.js`)
4. Type imports last (`import type { ... }`)

All relative imports use the `.js` extension suffix. This is a house convention (it is what the emitted ESM resolves), not something `verbatimModuleSyntax` requires.

## TypeScript Guidelines

This project uses **TypeScript 7.1.0-dev.20261106.1** with strict configuration.

### Required tsconfig flags

These are set in `tsconfig.base.json` and must not be overridden:

| Flag | Purpose |
|---|---|
| `target: "ESNext"` | Emit modern syntax, no downleveling |
| `module: "ESNext"` + `moduleResolution: "bundler"` | ESM module system, bundler-style resolution |
| `strict: true` | All strict checks enabled |
| `exactOptionalPropertyTypes: true` | `undefined` must be explicit in optional props |
| `noUncheckedIndexedAccess: true` | Array/object index access returns `T \| undefined` |
| `noUncheckedSideEffectImports: true` | Side-effect imports must resolve |
| `erasableSyntaxOnly: true` | No enums, no namespaces, no parameter properties |
| `isolatedDeclarations: true` | Every export must have an explicit type annotation |
| `verbatimModuleSyntax: true` | `import type` required for type-only imports |

### Patterns to use

- **Branded types** for IDs: `type ItemId = string & { readonly __brand: unique symbol }`
- **`satisfies`** on value expressions: `const config = { ... } as const satisfies Config`
- **`readonly` on all interface properties** -- immutability by default
- **`Disposable` protocol** on any class with cleanup needs

### Patterns to avoid

- **`enum`** -- Use `as const` objects or union types instead (blocked by `erasableSyntaxOnly`)
- **`namespace`** -- Use modules (blocked by `erasableSyntaxOnly`)
- **`class` parameter properties** -- Use explicit field declarations (blocked by `erasableSyntaxOnly`)
- **`any`** -- Use `unknown` and narrow
- **`forwardRef`** -- React 19 accepts `ref` as a prop

## Language Feature Usage

Use native features that the target browsers ship; the ones listed under helpers go through helper functions or a direct fallback.

### Native (use directly)

| Feature | Where Used | Example |
|---|---|---|
| Iterator Helpers (ES2025) | Machine, registry, search, WASM engines | `items.values().map(fn)`, `.toArray()` |
| `toSorted` / `toSpliced` (ES2023) | Machine, registry, fuzzy scorer, `<Command.Highlight>` | `results.toSorted((a, b) => b.score - a.score)` |
| `Symbol.dispose` / `using` (ESNext) | Machine, registry, search engine, keyboard, emitter, scheduler, frecency, WASM engines (consumers write `using` / `await using`) | `[Symbol.dispose]() { ... }` |
| `??=` (ES2021) lazy import | Frecency IndexedDB adapter | `idbModule ??= import('idb-keyval')` |
| `Promise.withResolvers` | WASM worker engine (`command-search-wasm`) | `const { promise, resolve } = Promise.withResolvers<void>()` |

### Cross-browser helpers (use helpers, not native)

| Feature | Helper | Location |
|---|---|---|
| Set methods | `setIntersection`, `setDifference`, `setUnion`, etc. | `core/utils/set-ops.ts` |
| `Map.groupBy` / `Object.groupBy` | `mapGroupBy`, `objectGroupBy` | `core/utils/group-by.ts` |
| `Temporal` | `Date.now()` | Direct usage (epoch ms) |
| `Promise.try` | `Promise.resolve().then(fn)` | Direct usage |
| `Math.sumPrecise` | `+= loop` | Direct usage |
| `String.isWellFormed` | `ensureWellFormed` | `core/utils/string-wellformed.ts` |

## Testing

### Unit Tests

**Config:** `vitest.config.ts`
**Environment:** happy-dom 21.0.4
**Files:** `packages/*/src/**/*.test.ts`, `tests/unit/**/*.test.{ts,tsx}`

```bash
# Run all unit tests
pnpm test

# Run in watch mode
pnpm test:watch

# Run with coverage
pnpm test:coverage

# Run a specific test file
pnpm vitest run tests/unit/search.test.ts
```

**Coverage thresholds** live in `coverage-thresholds.json` (currently lines 85, functions 80, branches 76, statements 83). They are enforced by `pnpm test:coverage` and by the CI Coverage job, and `scripts/coverage-ratchet.mjs` refuses to lower any of them relative to `origin/main`. The CI test matrix runs `vitest run` without coverage.

Coverage is collected with the V8 provider over `packages/*/src`. Excluded (see `vitest.config.ts`): test and bench files, `*.d.ts`, the three exact-path barrels (`modern-cmdk/src/core/index.ts`, `modern-cmdk/src/react/index.ts`, `command-search-wasm/src/index.ts`), the dead `react/primitives.ts`, and `command-search-wasm/src/wasm-engine.ts` and `worker.ts` (they import the wasm-pack output, which the unit run does not build).

#### Writing unit tests

- Test the core package in isolation -- no DOM, no React
- Test pure functions (scorers, parsers, matchers) with input/output assertions
- Test stateful objects (machine, registry, engine) by exercising the public API
- Use `using` for machine/registry cleanup in tests:

```ts
import { describe, it, expect } from 'vitest';
import { createCommandMachine, itemId } from 'modern-cmdk';

describe('CommandMachine', () => {
  it('should filter items by search query', () => {
    using machine = createCommandMachine({
      items: [
        { id: itemId('copy'), value: 'Copy' },
        { id: itemId('paste'), value: 'Paste' },
      ],
    });

    machine.send({ type: 'SEARCH_CHANGE', query: 'cop' });
    // Flush the scheduler
    const state = machine.getState();
    expect(state.filteredCount).toBe(1);
  });
});
```

Integration tests verify the React adapter with `@testing-library/react` and `@testing-library/user-event`:

pnpm vitest run tests/unit/  # Integration tests live alongside unit tests
```

These tests render React components with `happy-dom` and assert DOM state, ARIA attributes, and user interactions.

### Codemod fixtures

The codemod suites compare bytes, so every fixture is committed exactly as the test expects it and is never formatted (`tests/fixtures` is outside Biome).

**A transform case** is a directory `tests/fixtures/codemod/<transform>/<case>/` holding `input.<ext>` and `output.<ext>` (the same extension: `parserFor` in `packages/modern-cmdk-codemod/src/files.ts` picks the parser from it, and data-attrs routes `.css` and `.scss` to its stylesheet rewrite) and, when the transform reports manual work, `reports.json` (an array of strings; absent means no reports). Name the case the way its suite expects: an `import-rewrite` or `should-filter` case starts with the ledger row it proves (`ROW_ID` in `tests/unit/codemod-import-rewrite.test.ts` and `tests/unit/codemod-should-filter.test.ts`, for example `IR-1-...` or `SF-...`), a `forward-ref` case follows the same convention (`FR-1-ref-shorthand`), and a `data-attrs` case is `<NN>-<name>` and needs a title that starts with its row ids in `TITLES` in `tests/unit/codemod-data-attrs.test.ts` (a case without a title fails). Commit the files with LF line endings and without trimming the final newline: the helper `tests/unit/codemod-fixtures.ts` reads them as UTF-8, never trimmed, and the suites diff whole files. Do not commit a CRLF variant: every suite derives it with `toCrlf` on both sides and runs each case as LF and as CRLF; the forward-ref, import-rewrite and should-filter suites also run the transform on its own output and expect no change. `listCases(<transform>)` picks the case up, so apart from the data-attrs title no test needs editing; write the case first, watch it fail, then fix the transform.

**A CLI fixture** is a tree under `tests/fixtures/codemod-cli/` (today `mixed/`, with `mixed.expected/` holding the expected tree and the exact stdout and stderr per transform), driven by `tests/dist/cli-exec.test.ts` against the built bins (run `pnpm build` first). Two rules keep the repository honest about what git ignores:

- Commit the fixture's ignore file as `_gitignore`. The test copies the tree to a temporary directory and renames it to `.gitignore` there. A committed nested `.gitignore` would also act in this repository and hide files from `git add`.
- Leave the gitignored directories `gen/`, `dist/`, `node_modules/` and `coverage/` out of the fixture. The test writes them at test time, because the root `.gitignore` already ignores `dist/`, `node_modules/` and `coverage/` and a fixture file there could never be committed.

A test that needs a real work tree calls git through `tests/unit/git-fixture.ts` (`git()` and `gitEnv()`): no system or user config, a fixed identity, no signing and no autocrlf, so a developer's git settings cannot change the result.

### Updating the package snapshots deliberately

Two records pin what the package ships. Both change only in a commit that says so, and a diff of either is reviewed like code.

- **The tarball file lists** (`tests/package/modern-cmdk.files.json` and `tests/package/modern-cmdk-codemod.files.json`): after `pnpm build`, run `node scripts/check-package.ts --update`. It rewrites each file from its packed tarball (read in-process; never run a host `tar` on a tarball path, because Git's GNU tar reads a drive letter such as `C:` as a remote host). `pnpm check:package` without `--update` compares and fails on any difference.
- **The runtime export lists** (the expected arrays in `tests/dist/exports.test.ts`): edit them by hand, from the diff you intend. The test never writes them, and regenerating them from the test's own output would turn the check into a tautology.

## Performance Guidelines

### What to measure

1. **Bundle size** -- Run `pnpm size` after any code change. The CI rejects PRs that exceed the budget.
2. **Search latency** -- Run `pnpm bench` and compare the incremental-filter suites (`filter-10k`, `filter-100k`) with the full re-score timings; no gate asserts a ratio, and for broad prefixes incremental filtering is not faster (ledger P04).
3. **Re-render count** -- In the playground, use React DevTools Profiler. Each keystroke should trigger at most 2 re-renders (input + list).
4. **Memory** -- For large item sets (10K+), check heap size in DevTools. The registry uses `Map` + `Set` for O(1) operations.

### Budget constraints

| Entry | Limit | Method |
|---|---|---|
| `modern-cmdk` (core) | 6.5 kB | `dist/core/index.mjs`, gzip |
| `modern-cmdk/react` (adapter only) | 5.6 kB | `dist/react/index.mjs`, gzip; `modern-cmdk`, `react`, `react-dom` and `radix-ui` ignored |
| `modern-cmdk` + `modern-cmdk/react` | 10.1 kB | `dist/react/index.mjs`, gzip; only the React side ignored, so the one core is counted |
| `modern-cmdk/react/dialog` (adapter only) | 1.5 kB | `dist/react/dialog.mjs`, gzip; same ignore list as the adapter |
| `CommandSeparator` only | 5 kB | `import { CommandSeparator }` from `dist/react/index.mjs`, gzip; still contains the whole compound |
| `modern-cmdk/styles.css` | 4 kB | `dist/react/styles.css`, gzip |
| Codemod bin (`modern-cmdk`, deprecated) | 3.4 MB | `dist/codemod/*.mjs` plus `dist/codemod/transforms/*.mjs` (the bundled bin, shim included), installed size (no compression) |
| Codemod shim | 1000 B | `dist/codemod/bin.mjs` alone, installed size |
| `modern-cmdk-codemod` own files | 100000 B | `packages/modern-cmdk-codemod/dist/*.mjs` plus `dist/transforms/*.mjs`, installed size; `jscodeshift` excluded |

These limits are defined in the root `package.json` under `size-limit` and enforced by the `size` CI job. The measured figures are committed in `benchmarks/size-history/1.5.0.json` (056ab43, measured 2026-11-05 with size-limit 14.3.0): the bundled codemod bin is 3150191 B (3325793 B in 1.4), the shim 897 B and the `modern-cmdk-codemod` own files 97921 B. Pack it with `npm pack --dry-run --json` to see the tarball sizes the record also holds.

### Performance rules

- **No accumulating spread** -- Biome enforces `noAccumulatingSpread`. Use `Map`/`Set` mutations or pre-allocated arrays.
- **No barrel re-exports** -- Biome enforces `noBarrelFile` and `noReExportAll`. Each export is explicit.
- **Iterator Helpers over intermediate arrays** -- Use `.values().filter().map().toArray()` instead of creating temporary arrays.
- **Set methods over manual loops** -- Use `.intersection()`, `.difference()`, `.union()` for bulk ID operations.
- **Animate cheap properties** -- `styles.css` animates `opacity`, `scale`, `translate` and `background-color`; the dialog and overlay transitions (`styles.css:319-380`) are declared but inert until DT-19; never `width`, `top` or `left`. The one deliberate exception is the height of `[data-command-list]`: it declares `transition: height` with `will-change: height` (`styles.css:195-196`), but the library sets only `--command-list-height` on the list (the ResizeObserver height, `list.tsx:107`), so the height animates once the app sets `height: var(--command-list-height)` on `[data-command-list]` (as ARCHITECTURE.md says); no further reason is recorded in the code.

This project follows [Conventional Commits](https://www.conventionalcommits.org/):

```
<type>(<scope>): <description>

[optional footer(s)]
```

**Types:** `feat`, `fix`, `perf`, `docs`, `refactor`, `test`, `chore`, `ci`, `build`

**Scopes:** `core`, `react`, `wasm`, `docs`, `playground`, `ci`, `bench`

Examples:

perf(core): use Set.difference for bulk item removal
docs(architecture): add search pipeline diagram
test(core): add frecency decay edge cases

```

### Pull request process

1. **Branch** -- Create a branch from `main` using the naming convention above.

2. **Changeset** -- If your change affects published packages, create a changeset:
   ```bash
   pnpm changeset
   ```
   Select the affected packages and the semver bump type (patch, minor, major).

3. **Pre-commit hooks** -- Lefthook runs both in parallel:
   - `biome check --staged` -- lint and format staged files (`*.{ts,tsx,js,jsx,json,css}`)
   - `pnpm typecheck` -- the same type-check CI's lint job runs (on staged `*.{ts,tsx,vue}`; skipped during merge and rebase)

4. **Pre-push hooks** -- Lefthook runs them in order and stops at the first failure:
   - `pnpm --filter './packages/*' run build` -- always
   - then, in parallel: `vitest run --reporter=dot` (all unit tests) and `size-limit` (the budgets), the latter only when the push touches `packages/*/src/**`, a `packages/*/tsdown.config.ts` or the root `package.json`

5. **CI checks** -- The CI pipeline runs:
   - Lint and type-check (`pnpm lint`, `pnpm typecheck`)
   - Unit tests (3 OS, on Node 26.4.0 and the `.nvmrc` Node), React lanes, built-package tests, coverage with the ratchet
   - Rust & WASM, E2E tests (Chromium), docs build and render tests
   - Bundle size check (`size-limit`)
   - Package integrity (`pnpm check:package --pack-dir`, the codemod tarball smoke `scripts/codemod-tarball-smoke.ts`, the notices check `scripts/third-party-notices.ts --check`, `pnpm check:licenses`, an SPDX SBOM artifact `sbom` made with syft v1.56.0), the Consumer app matrix (next-turbopack, next-webpack, vite) and a Node 24 engine-strict install of the packed tarball
   - Templates (scaffold `react-basic`, `react-dialog` and `react-full` from the packed tarballs, `tsc -b` and build each; `scripts/template-smoke.ts --template all`, timeout 10 minutes)
   - Benchmarks (`pnpm bench:compare` against `benchmarks/baseline.json`, then `pnpm bench --run`)
   - Security audit (`pnpm audit`)

6. **Review** -- The `main` ruleset requires a pull request (0 approvals), the "CI Summary" check must pass, and force-pushes and deletion of `main` are blocked.

7. **Merge** -- Squash merge into `main`. The commit message should follow conventional commits.

## Architecture for New Contributors

If you are new to the codebase, here is the mental model:

```
User action (keystroke, click)
    |
    v
React adapter receives DOM event
    |
    v
Adapter calls machine.send({ type, payload })
    |
    v
Scheduler coalesces the update (rAF in browser, microtask in Node)
    |
    v
State machine processes the event:
  - SEARCH_CHANGE -> re-filter via search engine -> frecency re-rank
  - NAVIGATE -> compute new activeId
  - ITEM_SELECT -> fire onSelect, record frecency
  - OPEN/CLOSE/TOGGLE -> update dialog state
    |
    v
Machine emits 'stateChange' with new immutable state snapshot
    |
    v
useSyncExternalStore detects state change, triggers React re-render
    |
    v
Compound components read new state from context, render updated UI
```

**Key invariants:**

1. The core package never imports from `react`, `radix-ui`, or any DOM API.
2. State is always immutable -- every `setState()` creates a new object.
3. Every stateful class implements `Disposable`.
4. The machine's `.subscribe()` signature is `(listener: () => void) => () => void` -- the exact shape `useSyncExternalStore` requires.
5. The React components reach the consumer with the `'use client'` directive: the shipped `dist/react/index.mjs` and `dist/react/dialog.mjs` begin with `'use client'`, added as the banner of the React config in `packages/modern-cmdk/tsdown.config.ts`; no module under `src/react` carries the directive (`tests/dist/one-core.test.ts` enforces both).

**Where to start:**

| I want to... | Start here |
|---|---|
| Understand the state model | `packages/modern-cmdk/src/core/types.ts` |
| See how events are processed | `packages/modern-cmdk/src/core/machine.ts` |
| Understand search scoring | `packages/modern-cmdk/src/core/search/default-scorer.ts` |
| See how React connects to the core | `packages/modern-cmdk/src/react/context.ts` |
| Understand the animation system | `packages/modern-cmdk/src/react/styles.css` |
| Run the interactive demo | `pnpm --filter playground run dev` |

## Release Process

Releases are managed with [@changesets/cli](https://github.com/changesets/changesets).

### Creating a changeset

After making changes to any published package:

```bash
pnpm changeset
```

This prompts you to:
1. Select which packages are affected
2. Choose the semver bump type (patch, minor, major)
3. Write a summary of the change

The changeset is saved as a markdown file in `.changeset/`. Commit it with your PR.

### Publishing

When changesets are merged to `main`, the release workflow first waits (`ci-gate`) for the CI run on that same commit and stops unless it succeeded, so nothing is released for a commit whose CI is red or cancelled. It then:

1. Runs `pnpm version-packages` (`changeset version`, then `pnpm install --lockfile-only`) to update `package.json` versions, generate `CHANGELOG.md` entries and refresh `pnpm-lock.yaml`
2. Creates a release PR (`chore: release packages`) with the version bumps
3. When that PR is merged, builds the packages and runs `changeset publish` to publish to npm

Publishing authenticates via **npm OIDC Trusted Publishing** -- the workflow's `id-token: write` permission supplies a short-lived token, so no long-lived `NPM_TOKEN` secret exists. The publish job runs in the `npm` GitHub environment, which only the `main` branch may deploy to. Never push git tags manually; tag pushes can trigger publishing.

### Release tags

The legacy tags `v1.1.5`, the `v0.x` tags and `vscode-modern-cmdk@1.0.0` are kept as history. Every tag from `modern-cmdk@1.2.3` and `create-modern-cmdk@1.2.2` on is created by the release workflow, never by hand.

The `backfill` task (Actions > Release > Run workflow) is a temporary job meant to create the missing `modern-cmdk@1.2.2` and `create-modern-cmdk@1.2.1` tags and GitHub releases through the GitHub API; like every dispatched task it waits for CI on the dispatched commit first. Creating a release at those old commits needs a token with the Workflows permission, which the workflow's `GITHUB_TOKEN` cannot have, so the job fails with HTTP 403 until it is given such a token. It is deleted once every npm version has a GitHub release.

### Configuration

The changeset config (`.changeset/config.json`):

| Setting | Value | Meaning |
|---|---|---|
| `access` | `public` | Packages are published to the public npm registry |
| `baseBranch` | `main` | Changesets are resolved against `main` |
| `updateInternalDependencies` | `patch` | Internal workspace deps get a patch bump |
| `privatePackages` | `{ version: false, tag: false }` | Private packages (apps) are not versioned |
| `changedFilePatterns` | `["src/**", "package.json"]` | Only source changes trigger changesets |
| `changelog` | `@changesets/changelog-github` | Changelog entries link to GitHub PRs |

## Troubleshooting

### `.toArray is not a function`, `Symbol.dispose` undefined, or another missing language feature

The codebase uses Iterator Helpers (`.map`/`.filter`/`.toArray`), Explicit Resource
Management (`Symbol.dispose` / `using`) and `Promise.withResolvers` natively -- no polyfills.
Node.js 26.4.0+ ships all of them. If you hit one of these errors, your Node.js is too old:

```bash
node --version  # Must be >= 26.4.0; .nvmrc pins Node 28 nightly 28.0.0-nightly20261106ec4d4c2950
```

> [!NOTE]
> Standard features that the core does not call natively, so it does not depend on a runtime that ships them: Set methods (ES2025) and `Map.groupBy`/`Object.groupBy` (ES2024) go through the helpers in `core/utils/` (`set-ops.ts`, `group-by.ts`); `Promise.try` (ES2025) is written as `Promise.resolve().then(fn)`, `Math.sumPrecise` (ES2026) as a `+=` loop, and `Temporal` is not used (`Date.now()`). See [Language Feature Usage](#language-feature-usage).

### Biome reports `useImportType` errors

Type-only imports must use the `import type` syntax:

```ts
// Correct
import type { CommandState } from './types.js';

// Wrong
import { CommandState } from './types.js';
```

### Pre-commit hook fails with `biome check`

Make sure you have the correct Biome version. It is installed as a devDependency -- do not install it globally:

```bash
pnpm biome --version  # Should output 2.6.6
```

If hooks are not running, reinstall Lefthook:

```bash
pnpm lefthook install
```

### `size-limit` fails on pre-push

Your changes exceed the bundle size budget. Common causes:

- Added a new dependency to the core package
- Accidentally included a large import (check for unintended transitive deps)
- Used `export *` instead of explicit named exports

Run `pnpm size` locally to see the current sizes and identify what grew.

### E2E tests fail locally but pass in CI

- Make sure the playground is not already running on port 5173. Playwright starts its own instance.
- Install browser binaries: `pnpm playwright install --with-deps`
- Check that you have built all packages first: `pnpm build`

### TypeScript errors after pulling latest changes

```bash
# Clear build artifacts and reinstall
rm -rf node_modules packages/*/dist
pnpm install
pnpm build
pnpm typecheck
```

### Vite 8 HMR not working in the playground

The playground's `vite.config.ts` sets `strictPort: true`. If port 5173 is already in use, the server fails to start rather than silently picking another port. Kill any other process on port 5173 or change the port in `apps/playground/vite.config.ts`.

### WASM build fails

The WASM package requires Rust and `wasm-pack`:

```bash
# Install Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Install wasm-pack
cargo install wasm-pack

# Build WASM
pnpm --filter modern-cmdk-search-wasm run build:wasm
```

The WASM build is not required for developing the core or React packages.
