## 1. Scope

The roadmap scope, as it maps onto the code at b145c15:

- **Lifecycle and options.**
  - A StrictMode- and Activity-safe machine through a public `suspend()` / `resume()` pair (RA-03, ARCH-19, CE-124; D102).
  - The machine disposes only a search engine it created (D103).
  - Latest-ref options, and the `items` prop diffed into register/unregister (RA-04, RA-21, ARCH-17).
  - Sync input with deferred refilter (ARCH-03).
  - Idempotent OPEN/CLOSE (ARCH-18, CE-48, CE-117, CE-118).
  - Controlled search and activeId, and a `searchEngine` alias (ARCH-29).
  - An `id` prop on Item and Group, with `forceId` as a @deprecated alias (D29).
  - @deprecated `isPending`, `startTransition` and `setOptimisticActiveId` (RA-16, ARCH-27, P27, RA-23).
- **Components.**
  - AsyncItems registers through one path and unregisters on unmount.
  - `propsMerge` (RA-13).
  - One Group tree (RA-05).
  - Root div props and exactOptionalPropertyTypes-safe props (RA-32, ARCH-30).
  - The SSR platform (RA-19, CE-13) and SSR registration (RP-31).
  - Separator during search, the ErrorBoundary reset, Server Component access.
- **Telemetry and devtools.**
  - A wired telemetry option on the monotonic clock (CE-18, CE-19, ARCH-32, CE-74, SEC-47).
  - Devtools under `__MODERN_CMDK_DEVTOOLS__` and `modern-cmdk-devtools`, with the old names as deprecated aliases (D30, SEC-32), and one event per change (RA-48).
- **cmdk parity.** A differential cmdk 1.1.1 suite replaces the tautologies. A checked-in delta table holds one row per case.
- **WASM index.** `index()` upserts and `remove()` deletes in the main-thread engine (CE-116).
- **Docs and comments**, after the code they describe.

**Out of scope (1.8.0 and later).**
- Keyboard: the IME guard, `keyboardScope`, modifier checks, layered Escape (RA-15, RA-37, RA-38, A11Y-*).
- The announcer, shortcut labels, CSS tokens, the playground (PG-*), axe and screenshot E2E.
- The ErrorBoundary demo reset (PG-06, 1.8.0).
- Highlight ranges (DAE-39, 1.9.0).
- The worker engine (W03, W06, W07, ARCH-04, SEC-21 and the rest; 1.11.0/1.12.0).

**Design.** F1 to F8 name the findings of the C1 design review that G-53 rules on.

*Lifecycle (RA-03, ARCH-19, CE-124; D102).*
- The defect:
  - `use-command-setup.ts:37-41` keeps the machine in a null-guarded lazy `useRef` initializer. That part is sound: it runs once per mount, StrictMode's second render pass included (`react-dom-client.development.js:8331-8357` reuses the ref).
  - `:52-57` disposes the machine in the passive-effect cleanup and nulls the ref.
  - StrictMode's simulated unmount and Activity's hide both run that cleanup and then the setup with no re-render. The subtree keeps the disposed machine (`context.ts:33-41` stable context). The global shortcut listener is detached for good (`keyboard/index.ts:127,130-135`). The next render builds a fresh machine that holds no query.
- The target (D102): a public `suspend()` / `resume()` pair on `CommandMachine` (`machine.ts:36-50`), documented and kept through 2.0.
  - `suspend()` detaches every global hold the machine owns (the inventory below), flushes a pending frecency save through the engine's existing `flush()` path (`frecency/index.ts:188-195`), and unregisters the leak sentinel. `resume()` re-attaches and re-arms them.
  - Both are idempotent and no-ops on a disposed machine. State, registrations, the engine and the storage stay.
  - The React root keeps one machine per mount in the null-guarded lazy `useRef` initializer. It suspends in its layout-effect cleanup and resumes in its layout-effect setup.
  - StrictMode's replay and an Activity hide/show therefore keep the machine, its query, its registrations and its identity: `CommandStableContext` consumers see one machine. There is no successor and no seeding.
  - The lifecycle runs in a layout effect (F8). A passive-effect resume would leave one painted frame in which keys reach a suspended machine. StrictMode replays layout effects synchronously (`react-dom-client.development.js:22087-22102`), and the server dispatcher's `useLayoutEffect` is a no-op (`react-dom-server.node.development.js:11376`).
  - React's path never disposes terminally. A suspended machine holds no global reference, so a real unmount leaves it to the collector. The D102 collection test proves it on the MEM-3 pattern of 60a9f96 (`tests/unit/memory-leak.test.ts:28-44`).
  - The machine registers itself at construction with a FinalizationRegistry that releases an engine it created once the machine is collected. An explicit `machine[Symbol.dispose]()` or `using` releases it earlier and stays the documented teardown.
  - Dispose stays terminal (CE-107, CE-113).
- The holds, from the code at b145c15 and the review's F1. `suspend()` detaches each and `resume()` re-arms it, and each has its own D102 test:
  - The document keydown listener. `machine.ts:99` constructs the KeyboardShortcutRegistry, whose constructor attaches it (`keyboard/index.ts:32-35,109-128`); `:130-135` detaches it. The item bindings (`machine.ts:137-141,236-243`) stay registered while it is detached.
  - The pagehide and visibilitychange listeners (`frecency/index.ts:96-102`). They are attached with `#abort`'s signal, which stays the dispose signal (it also gates the debounce at `:153`), so suspend detaches them through a signal of their own.
  - Scheduled work. The scheduler's pending frame (`utils/scheduler.ts:64-74`) is flushed through `flush()` (`:53-61`), so no rAF or microtask stays queued. The frecency debounce timer (`frecency/index.ts:151-153`) is flushed through the save above.
  - The leak sentinel of the built-in engine. `search/index.ts:52-56` registers it and `:159-161` unregisters it. A suspended machine is not a leak, so suspend unregisters it and resume registers it again.
- Public API: `suspend()` and `resume()` (D102), and the `searchEngine` alias (ARCH-29, below). The rest of C1 changes no signature.

*Engine ownership (D103).*
- `machine.ts:435` disposes the search engine unconditionally, a caller's included. After one Activity hide at b145c15, a caller's WASM engine throws `disposed` on its next call (`apps/docs/api/command-search-wasm.md:66`).
- The machine disposes a search engine only if it created it: `ownsEngine = (options.searchEngine ?? options.search) === undefined`. That mirrors FrecencyEngine's `#ownsStorage` (`frecency/index.ts:84,233-235`). A caller's engine is the caller's to dispose and survives the machine's dispose, suspend and resume.
- No documented contract covers ownership either way (`types.ts:198`, `apps/docs/api/command-react.md:62`). D103 rules the change as the bug fix that makes DAE-64 and DAE-66 true. C1a states the rule in the `search` and `searchEngine` JSDoc, and C6 states it in the docs.
- Test: "D103: a caller's searchEngine is not disposed by the machine and keeps working after an Activity hide/show".

*Disposal paths.*
- CE-113: `machine.ts:385-401` `send()` returns at once after dispose, so no reducer runs and no option callback fires.
- CE-78: `scheduler.ts:64-75` refuses to schedule after `[Symbol.dispose]` (`:78-86`) through a `disposed` flag.
- CE-107: the clamp is moot once a disposed machine refuses sends. The test proves reuse is impossible.
- CE-110: the hydration commit in the load `.then` (`machine.ts:111-118`) runs through the scheduler. A throwing listener then surfaces as an uncaught exception, as it does from a `send()` batch.

*Frecency.*
- CE-111: `frecency/index.ts:169-172` clears dirty only when the queued save resolves, and sets it again on rejection. That keeps the one-warning rule and never writes after a rejected load (D96).
- CE-112: `idb-storage.ts` routes store creation through one shared upgrade promise per database name. A `VersionError` open is retried once with the current version.

*Latest-ref options (RA-04, RA-21, ARCH-17).*
- The defect: `command.tsx:42-45` and `dialog.tsx:47-57` build the machine from the first render's props.
- The target, in the adapter:
  - The root passes `createCommandMachine` a stable options object.
  - Its callbacks (`onSelect`, `onActiveChange`, `onSearchChange`, `onOpenChange`, and `telemetry` once C3 lands) are trampolines over a latest-props ref. The ref starts as `useRef(props)` and is assigned in `useLayoutEffect`, so render writes nothing (RA-58's rule). Construction fires no option callback, so the first render needs no assignment.
  - Only the `onSearchChange`, `onActiveChange` and `onOpenChange` trampolines dedupe (F4): each forwards a value only when it differs from the last one forwarded. The memory lives in the hook-scoped stable options object and starts from the machine's state. The dedupe names `types.ts:201,205` as its contracts ("Callback fired when the active (highlighted) item changes", "Callback fired when the search query changes").
  - `onSelect` never dedupes: selecting one item twice fires twice.
  - In controlled mode the `onOpenChange` trampoline forwards nothing. A user-initiated change reaches the consumer only through the Radix path (*Open state*, below).
  - Its `loop`, `filter` and `disabledItems` are getters over the same ref. The machine reads them at use time: `machine.ts:251` reads `loop`, `:166` and `:89` read `filter`, `:189` reads `disabledItems`.
  - A `disabledItems` change refilters (F6). Nothing re-reads `:189` until the next filter pass, so the diff effect marks the results dirty: through UPDATE_ITEM, or an internal refilter event if C1a adds one.
  - A layout effect diffs the `items` and `groups` props by id into REGISTER_ITEM/UPDATE_ITEM/UNREGISTER_ITEM and REGISTER_GROUP/UNREGISTER_GROUP sends. Its baseline belongs to the machine and resets whenever the hook's machine changes (F6).
- These stay init-only, documented, with a development warning on change:
  - `shortcutAction` (F6). The machine reads it only at bind time (`machine.ts:235`) and freezes it into each handler (`:240`); under `'direct'` an item without `onSelect` is never bound.
  - Switching `filter` between a function and `undefined`. It selects the engine at `machine.ts:82-96`.
  - `frecency`, and `search`/`searchEngine`.
- cmdk 1.1.1 reads its filter through a props ref and does not refilter on a filter change, so the next query using the new function is parity.

*Open state.*
- `machine.ts:157-161` `setOpen` returns when `state.open === open`. This is a bug fix restoring `types.ts:203`, "Callback fired when the dialog open state changes". It fixes ARCH-18, CE-48 and CE-117, and keeps a repeated CLOSE silent (CE-118).
- Radix owns Escape in the dialog (F5).
