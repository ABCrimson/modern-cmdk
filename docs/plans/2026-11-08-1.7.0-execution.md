## 1. Scope

The roadmap scope, as it maps onto the code at b145c15:

- **Lifecycle and options.**
  - A StrictMode- and Activity-safe machine (RA-03, ARCH-19, CE-124).
  - Latest-ref options, and the `items` prop diffed into register/unregister (RA-04, RA-21, ARCH-17).
  - Sync input with deferred refilter (ARCH-03).
  - Idempotent OPEN/CLOSE (ARCH-18, CE-48, CE-117, CE-118).
  - Controlled search and activeId, and a `searchEngine` alias (ARCH-29).
  - An `id` prop on Item and Group, with `forceId` as a @deprecated alias (D29).
  - @deprecated `isPending`, `startTransition` and `setOptimisticActiveId` (RA-16, ARCH-27, P27, RA-23).
- **Components.**
  - AsyncItems registers through one path and unregisters on unmount.
  - `propsMerge` (RA-13).
  - One Group tree (RA-05).
  - Root div props and exactOptionalPropertyTypes-safe props (RA-32, ARCH-30).
  - The SSR platform (RA-19, CE-13) and SSR registration (RP-31).
  - Separator during search, the ErrorBoundary reset, Server Component access.
- **Telemetry and devtools.**
  - A wired telemetry option on the monotonic clock (CE-18, CE-19, ARCH-32, CE-74, SEC-47).
  - Devtools under `__MODERN_CMDK_DEVTOOLS__` and `modern-cmdk-devtools`, with the old names as deprecated aliases (D30, SEC-32), and one event per change (RA-48).
- **cmdk parity.** A differential cmdk 1.1.1 suite replaces the tautologies. A checked-in delta table holds one row per case.
- **WASM index.** `index()` upserts and `remove()` deletes in the main-thread engine (CE-116).
- **Docs and comments**, after the code they describe.

**Out of scope (1.8.0 and later).**
- Keyboard: the IME guard, `keyboardScope`, modifier checks, layered Escape (RA-15, RA-37, RA-38, A11Y-*).
- The announcer, shortcut labels, CSS tokens, the playground (PG-*), axe and screenshot E2E.
- The ErrorBoundary demo reset (PG-06, 1.8.0).
- Highlight ranges (DAE-39, 1.9.0).
- The worker engine (W03, W06, W07, ARCH-04, SEC-21 and the rest; 1.11.0/1.12.0).

**Design.**

*Lifecycle (RA-03, ARCH-19, CE-124).*
- The defect:
  - `use-command-setup.ts:37-41` creates the machine in render into a ref.
  - `:52-57` disposes it in the effect cleanup and nulls the ref.
  - StrictMode's simulated unmount and Activity's hide both run that cleanup and then the setup with no re-render. The subtree keeps the disposed machine (`context.ts:33-41` stable context). The global shortcut listener is detached for good (`keyboard/index.ts:127,130-135`). The next render builds a fresh machine that holds no query.
- The target: the machine lives in `useState(factory)`, so render writes no ref. The cleanup queues disposal (`queueMicrotask`) instead of running it.
  - A setup that runs in the same task cancels it. That is StrictMode's replay, and an Activity show inside the task.
  - When the queued disposal has run (Activity hidden past the task), the setup creates a successor. It seeds the successor from the last snapshot the hook holds (search, page and pageStack, open, activeId) and puts it into state. Children re-register through their `[stable.machine, id]` deps (`use-register.ts:48,67-75`).
  - The callback trampolines forward a change only when the value differs from the last one forwarded, so seeding fires no `onSearchChange` or `onOpenChange`.
  - A caller's frecency storage and a caller's search engine survive the successor. D95 covers the storage; the engine is never disposed by React's path (see DAE-64 and DAE-66 in C6).
- Public API: none. Question 5 names the alternative, a core `suspend()`/`resume()` pair.

*Disposal paths.*
- CE-113: `machine.ts:385-401` `send()` returns at once after dispose, so no reducer runs and no option callback fires.
- CE-78: `scheduler.ts:64-75` refuses to schedule after `[Symbol.dispose]` (`:78-86`) through a `disposed` flag.
- CE-107: the clamp is moot once a disposed machine refuses sends. The test proves reuse is impossible.
- CE-110: the hydration commit in the load `.then` (`machine.ts:111-118`) runs through the scheduler. A throwing listener then surfaces as an uncaught exception, as it does from a `send()` batch.

*Frecency.*
- CE-111: `frecency/index.ts:169-172` clears dirty only when the queued save resolves, and sets it again on rejection. That keeps the one-warning rule and never writes after a rejected load (D96).
- CE-112: `idb-storage.ts` routes store creation through one shared upgrade promise per database name. A `VersionError` open is retried once with the current version.

*Latest-ref options (RA-04, RA-21, ARCH-17).*
- The defect: `command.tsx:42-45` and `dialog.tsx:47-57` build the machine from the first render's props.
- The target, with no core change:
  - The root passes `createCommandMachine` a stable options object.
  - Its callbacks (`onSelect`, `onActiveChange`, `onSearchChange`, `onOpenChange`, and `telemetry` once C3 lands) are trampolines over a latest-props ref, assigned in `useLayoutEffect`, so render writes nothing (RA-58's rule).
  - Its `loop`, `filter`, `disabledItems` and `shortcutAction` are getters over the same ref. The machine reads them at use time: `machine.ts:251` reads `loop`, `:166` and `:89` read `filter`, `:189` reads `disabledItems`, `:235` reads `shortcutAction`.
  - A layout effect diffs the `items` and `groups` props by id into REGISTER_ITEM/UPDATE_ITEM/UNREGISTER_ITEM and REGISTER_GROUP/UNREGISTER_GROUP sends.
- These stay init-only, documented, with a development warning on change: switching `filter` between a function and `undefined` (it selects the engine at `machine.ts:82-96`), `frecency`, and `search`/`searchEngine`.
- cmdk 1.1.1 reads its filter through a props ref and does not refilter on a filter change, so the next query using the new function is parity.

*Open state.*
- `machine.ts:157-161` `setOpen` returns when `state.open === open`. This is a bug fix restoring `types.ts:203`, "Callback fired when the dialog open state changes". It fixes ARCH-18, CE-48 and CE-117, and makes Escape's two CLOSEs (`use-keyboard.ts:53-56` plus Radix) one callback (CE-118).
- Controlled mode (RA-35, DG-20, RA-34, DGX-CD-5): `dialog.tsx:93` binds `Dialog.Root open={controlledOpen ?? state.open}`.
  - When controlled, the Radix `onOpenChange` (`:85-90`) and the document Escape path call the consumer's `onOpenChange` and send nothing. The prop drives the machine through the sync effect (`:69-73`), which skips when the prop equals `state.open`.
  - A parent that keeps `open={true}` keeps the dialog open: a veto. That restores the "controlled" contract the `open` row of `apps/docs/api/command-react.md:392` names.
- RA-X3: `dialog.tsx:76-82` focuses the input through a ref to `Dialog.Content` (`querySelector('[data-command-input]')`), not `document.getElementById`, so a shadow-root container works.

*ARCH-29.*
- `types.ts:198` gains `searchEngine?: SearchEngine | undefined`. `search` becomes `@deprecated` (removed in 2.0), and `machine.ts:82-83` reads `options.searchEngine ?? options.search`.
- `Command.Input` (`input.tsx:13-16`) accepts `value` (controlled) next to `onValueChange`:
  - The input shows `value`.
  - A change calls `onValueChange` and no machine send.
  - A layout effect sends SEARCH_CHANGE when `value` changes.
- Controlled `activeId`: a core option `activeId?: ItemId | null | undefined`, read live.
  - While it is defined, activations whose id differs from it (navigate, pointer, the refilter fallback at `machine.ts:208-211`) call `onActiveChange(candidate)` and leave `state.activeId`.
  - ITEM_ACTIVATE for the prop's own id applies. The root sends it when the prop changes.
- All of it is additive.

*Deprecations (ARCH-27, RA-23).*
- `isPending` (`use-command.ts:19`, `context.ts:16-17,46-47`) and `setOptimisticActiveId` (`use-command.ts:23`, `context.ts:19,40`) gain `@deprecated` JSDoc naming 2.0 removal. Behaviour is unchanged.
- C2 removes the one internal caller (`item.tsx:66`).

*RA-36.* `use-command-state.ts:18-27` drops the render-time `selectorRef` write. `getSnapshot` is memoized on `[machine, selector]` and caches `{state, value}` by machine-state identity, so a fresh-object selector returns the same value for the same state. An optional `isEqual` is additive.

*RA-32.* `CommandRootProps` (`command.tsx:27-31`) extends `Omit<ComponentPropsWithRef<'div'>, keyof CommandMachineOptions | 'children'>`, and the rest spreads onto the root div (`:66-73`). The external ref merges with `rootRef` through a React 19 ref callback with cleanup.

## 8. Risks

- **Lifecycle regressions.** C1 changes when the machine is disposed.
  - The EG tests precede the fix, and the C1 verifier probes StrictMode, Activity, unmount, the Dialog, and a caller-owned engine and storage.
  - A machine discarded by StrictMode's double render leaves its frecency load to resolve into an undisposed, unreferenced machine. The `disposed` check at `machine.ts:115` does not cover it. The load only merges; it writes nothing, by D96's rule.
- **Size.** Section 6's forecast exceeds D90 on every adapter row. If the ruling refuses a raise, there are two levers:
  - RA-23's implementation as a plain ITEM_ACTIVATE, dropping `useOptimistic` and `useTransition`. That is a behaviour change needing its own LD-05 ruling.
  - Deferring the controlled `activeId` to 1.10.0.
- **LD-05 exposure.**
  - These are bug fixes naming a quoted contract: the idempotent OPEN/CLOSE (`types.ts:203`), the controlled-dialog veto (`command-react.md:392`), and the `id` taking over the DOM id.
  - The changes without one sit behind options defaulting to today: `propsMerge`, `alwaysRender`, `redactQuery`.
- **Stacking on an unmerged 1.6.0.** b145c15 is release/1.6.0's head. A 1.6.0 fix after b145c15 re-enters 1.7.0 by cherry-pick (question 1).
- **cmdk 1.1.1 under the experimental React and happy-dom.** The CMP-9 case at `cmdk-comparison.test.tsx:1264` already renders it. A case cmdk cannot run in happy-dom is a delta row (`'differs'`, reason "environment"), not a skip.
- **The macOS emulation.** Playwright's `userAgent` option alone leaves `navigator.platform` at the host's value, so the harness asserts the emulated platform before counting.
