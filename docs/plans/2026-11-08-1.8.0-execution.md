## 1. Scope

The roadmap scope, as it maps onto the code at 527dc8c5:

- **Keyboard (C3).**
  - One IME guard: the React keydown handler and the shortcut registry return on `event.isComposing` or `keyCode === 229` (RA-15, A11Y-05; `react/hooks/use-keyboard.ts:26-28`, `core/keyboard/index.ts:113-125`).
  - `keyboardScope: 'root' | 'combobox'`, default `'root'` (today's behaviour), with a development warning (A11Y-16).
  - `defaultPrevented` honoured on every key, layered Escape, inline Escape inert while closed (A11Y-14, A11Y-17, RA-38).
  - A pointer press on an item does not take focus from the input (A11Y-15, C5, `item.tsx` owner).
  - Focus returns to the opener when the dialog closes, which restores `apps/docs/guide/accessibility.md:286` ("returns focus to the previously focused element"; the roadmap cites the line as :249 at its writing) (A11Y-02).
  - Navigation order equals DOM order (RA-02, A11Y-03; C4).
- **Announcer v2 (C5).** Empty and Loading render outside the listbox from the first render, which restores `react/empty.tsx:3` ("Portals into a container outside the listbox for valid ARIA structure"). The result count is debounced and silent while loading, which restores `accessibility.md:132` ("announcements wait until the user pauses"). Loading is polite (RA-14, RA-X10, A11Y-10 to A11Y-12, DG-50, RA-54).
- **Shortcuts (C2, C5).**
  - Valid `aria-keyshortcuts` (A11Y-18, DT-51, DAE-36, DG-47, DGX-SC-6, RA-53) and a true `Meta` label (CE-12, A11Y-20, DG-68).
  - An `event.code` fallback, and AltGr never matching Ctrl+Alt (CE-11, A11Y-21). The `+` key, key casing, the macOS glyph order (CE-40, CE-42, CE-41).
  - Editable targets skipped behind `shortcutsInEditable: false`: `true` (today) stays the 1.x default and 2.0 flips it (roadmap call). The opt-in shortcut scope (A11Y-06).
- **CSS (C6).**
  - The stylesheet is built, not copied (PKG-10; D58 put it at 1.8.0). Tokens move to `:where(:root, :host)` inside `@layer command.base` (A11Y-01, DT-19, RA-10, RA-31). Only the reduced-motion rule is scoped (RA-12).
  - transform-origin and the RTL flip (RC-2, A11Y-33), exit animations (RA-11), `clip-path` (RA-60, A11Y-34), fade edges (RA-52), the forced-colors highlight (A11Y-37), the loading pulse (A11Y-40), RA-X8, RA-X9.
  - `list.tsx:120` drops `behavior: 'smooth'` (A11Y-22, in C5 with `list.tsx`).
  - The announcer and the dialog title stop depending on the global `.sr-only` (RA-09, C5).
- **Playground (C7).** The broken demos (PG-01, PG-03, PG-05, PG-06, PG-15, PG-19) and the pass-2 playground rows.
- **E2E (C1, C8).**
  - The foundation first (C1): self-hosted fonts, `reducedMotion: 'reduce'`, a shared fixture that fails on any off-origin request, hard preconditions instead of early returns, an observable selection. Then Firefox and WebKit in the default projects (TEB-81).
  - Then the a11y and visual gate (C8): wcag22aa (SPEC-38), retrying assertions, computed accessible names, axe on every route in both themes (PG-07), and `toHaveScreenshot` baselines in light, dark, forced-colors and `dir=rtl` (the roadmap's G8, no ledger row).
  - The NVDA smoke is a call (7).
- **Docs and comments (C9),** after the code they describe.

**Out of scope.**
- `ariaNotify` (roadmap "Announcer v2", Opp #7): no installed type declares it. Re-arm: TypeScript's `lib.dom.d.ts` declares it and two engines ship it. No ledger row exists.
- The 2.0 halves of three rows, which change a 1.x default (call 5):

  - Display order is `groupedIds` (`machine.ts:265-268`): groups by priority. The sort is stable, so equal priorities keep the first-appearance order of their best item, which is cmdk's group order. Items inside a group are in score order.
  - `navIds` becomes `groupedIds.values().flatMap((ids) => ids).filter(isEnabled).toArray()`. These are ES2025 iterator helpers, the form `machine.ts` already uses at `:262`.
  - The candidate at `:274-277` is then the first enabled item in display order. With default priorities that is still the global best match. With differing priorities it is the first item of the first group (call 13). `filteredIds`, a public state field, keeps its score order.
  - List, DOM mode only: a layout effect keyed on `state.groupedIds` puts the nodes in that order.
    - Inside each `[data-command-group-items]` container and in the list's own item container, the effect appends each item node in order. In the list container, it appends each group element at its group's position.
    - A node already preceded by its predecessor is not touched, so a refilter that keeps the order writes nothing.
    - The algorithm is cmdk 1.1.1's `sort` (`node_modules/cmdk/dist/index.mjs`, the function that calls `appendChild` on `[cmdk-group-items]` children and then on the groups). Its input is the machine's order instead of DOM scores.
  - The empty query lists items in registration order, which `guide/frecency.md:35` documents ("the empty query, and every query under `filter={false}`, list the items in registration order"). The effect applies it too, so DOM order equals navigation order in every state.
  - Virtual mode already renders by index in `filteredIds` order (`list.tsx:118`). It has no groups until RA-08 (1.9.0), so it needs no change: with no group, the grouped order equals `filteredIds`.
- *Why not CSS `order`.* RA-02's fix offers it, but A11Y-03's forbids it: screen readers follow DOM order, not visual order.
- *React and moved nodes.*
  - React removes a node by reference.
  - React inserts a new node with `insertBefore` against the next host sibling in fiber order, which may have moved. The layout effect re-sorts after every commit that changes `groupedIds`, so a misplaced insert lasts no frame.
  - The test mounts and unmounts items mid-search under StrictMode.
  - Separators (`alwaysRender` defaults to `true` in 1.x, D101) move with the group that follows them in source order. The design review rules whether that is right.
